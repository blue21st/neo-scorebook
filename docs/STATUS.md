## 2. 機能一覧

### チーム・選手

- 初回起動時のチーム登録、設定画面でのチーム名変更
- 選手の登録・編集・削除（背番号・名前）

### オーダー登録

- 自チーム：登録選手から選択、守備位置設定（投・捕・一〜右・DH）、「登録選手を一括セット」
- 相手チーム：チーム名・背番号・名前・守備位置を手入力
- 打順のドラッグ並び替え（タッチ対応、浮き上がって追従する演出つき）
- 打順とは別に先発投手を登録（DH制対応）
- ベンチ選手の登録

### 試合記録

- 投球入力：ボール、見逃し、空振り、ファウル、インプレー。BSOカウントと投球数を自動管理
- 打席結果：打球方向（投〜右の9方向）× 結果。セーフ系はヒット、セーフティバント、二塁打、三塁打、本塁打、エラー、FC（野選）。アウト系はゴロ、フライ、ライナー、送りバント、バント、犠飛、ファールフライ、ファールライナー、併殺打
- 特殊：死球、故意四球、振り逃げ（1塁走者あり・2アウト未満では不成立として三振処理）
- 進塁確認：打席結果のあと走者ごとに進塁先を確認（3塁→2塁→1塁の順）。押し出しは自動
- 走塁アクション：盗塁成功、盗塁死、牽制セーフ、牽制アウト、WP進塁、PB進塁、直前プレー進塁、その他進塁、その他アウト（その他2つはコメント入力つき）
- 選手交代：代打・代走・守備交代。複数同時交代に対応。代打時は退く打者の守備位置を引き継ぐ
- 3アウトでの攻守交代、イニング進行、打順の継続
- 1手戻す（操作前の状態をスナップショットで保持）
- 試合情報の編集（日付、種別＝公式戦／練習試合、大会名、相手チーム名）

### 試合の終了・保存

- 終了種別：試合終了、コールド／早期終了（理由：コールド、時間切れ、天候不良、その他）、中断して保存
- 中断試合の再開
- 2回目以降の保存は同じ行を update（重複行を作らない）
- 試合の削除

### 表示

- 記録タブ：スコアボード（イニング別得点）、ダイヤモンド、現在の打者・投手
- 経過タブ：イニングごとの打席ログ、選手交代、得点経過
- 成績タブ（試合内）：打者成績・投手成績。得点は `gameLog` から算出
- 試合一覧：結果サマリーカード、種別フィルタ
- 通算成績：全登録選手を表示（未出場は「-」でグレーアウト）、ソート、種別・期間フィルタ、選手別の詳細（打率・出塁率・長打率・OPS・wOBA）

### 開発基盤

- ロジックのユニットテスト 87件、Playwright の基本操作テストと3イニング通しテスト
- Claude Code 用レビューコマンド：`/review-bug`、`/review-style`、`/review-design`
- ファビコン、iOSホーム画面アイコン

## 4. 既知の課題

### 対応が必要

1. **push がまだ。** コミットは済んでいるが、push するまで本番は 8/11 版のまま。
2. **本番モードの確認は簡易なもののみ。** Supabase をダミーに差し替えた環境で、開発モードでは阪神オーダーが出ること、本番ドメインでは出ないことを確認した。実際の本番DBにつないだ確認は push 後に行う。
3. **`season` / `game_type` / `tournament` カラムの適用確認。** 8/11の本番版もすでにこのカラムを読み書きしている。DDLへの反映が後追いになっているだけなら問題ないが、Supabase側を確認する。
4. **フォルダ移動後のデプロイ未検証。** `deploy.yml` のパスは書き換えたが、実際に動かしてはいない。
5. **Playwright テストがフォルダ移動後に未実行。** URLは変わらないが、サーバーを `neo-scorebook/` で起動する必要がある。

### 構造上の懸念

6. **認証がない。** Supabase の anon キーで直接読み書きし、チームは `nsb_teams` の先頭1件を使う。1チーム専用の作りで、URLを知っていれば誰でも編集できる可能性がある。RLSの設定状況は要確認。
7. **`nsb_teams` / `nsb_players` のDDLがリポジトリにない。** 環境を作り直せない。
8. **試合とチームの紐付けがチーム名。** `nsb_games.team_name` で絞り込んでいるため、チーム名を変更すると過去の試合が通算成績から外れる可能性がある。
9. **`.DS_Store` が git に追跡されたまま。** `.gitignore` は 2026-11-14 に追加したが、すでに追跡されている分は `git rm --cached .DS_Store` で外す必要がある。
10. **本体が約4,900行の単一HTML。** `GameRecordScreen` だけで約1,700行ある。
11. **Playwright テストが本番DBに依存。** テスト用データと本番データが分かれていない。

BALLSTATS 側の課題。

- 自動デプロイの対象外
- テストがない
- `players` / `games` のテーブル作成文がリポジトリにない
