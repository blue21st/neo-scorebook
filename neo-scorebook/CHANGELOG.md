# neo-scorebook 変更ログ

neo-scorebook（試合中に1球ずつ記録するアプリ）の版ごとの変更履歴。**新しい版が上**。
初めて見る人は、まず「このファイルの使い方」と最新の版だけ読めばよい。

- アプリの現状・既知の不具合・次にやること → [docs/STATUS.md](../docs/STATUS.md)
- 2本のアプリ（neo-scorebook / BALLSTATS）の関係 → [docs/INTEGRATION.md](../docs/INTEGRATION.md)
- BALLSTATS 側の履歴 → `ballstats/archive/`（版ごとのファイル）と [docs/history/](../docs/history/)（開発ログ）

## このファイルの使い方

- 版番号は `neo-scorebook.html` 内の `APP_VERSION`（例 `v2026.11.23-4`）。形式は `vYYYY.MM.DD-連番`。画面上部にも出る。
- 版が変わるたびに、**変更前の版を `archive/neo-scorebook_<版番号>.html` に残す**（BALLSTATS の `archive/` と同じやり方）。いまの版は `neo-scorebook.html` 本体が現行で、`archive/` には「その1つ前まで」が入る。
- 戻したいときは、`archive/` の該当ファイルを `neo-scorebook.html` に上書きコピーする。ただし DB の保存形式が変わった版をまたぐときは「注意」欄を見ること。
- 古い版でアーカイブが無いものは、`git` の履歴から取り出せる（コミットは各版の欄に記載）。例: `git show 475f06f:neo-scorebook.html > old.html`（フォルダ再編前は `neo-scorebook.html` がリポジトリ直下にあった）。
- 本番（`https://baseball.versus.jp/`）に出ているのは `main` ブランチの版。`online-test` ブランチは `https://baseball.versus.jp/test/` に出る試験用で、本番とは別。各版の「公開状況」を見る。

### 更新のしかた（開発者向けの手順）

1. `neo-scorebook.html` を変える前に、いまの版を `archive/neo-scorebook_<いまの版番号>.html` にコピーする（まだ無ければ）。
2. `APP_VERSION` を上げる。
3. このファイルの先頭（「新しい版が上」の一番上）に、版の欄を足す。書くこと: 日付、何を変えたか、**なぜ変えたか（依頼・不具合の経緯）**、注意（DB・他の画面への影響）、アーカイブ名、コミット。
4. 大きな変更なら [docs/STATUS.md](../docs/STATUS.md) の「機能一覧」「既知の課題」も直す。

## v2026.11.23-6（2026-11-23）— 経過ページをテキスト速報の形式に／過去の対戦チームの一覧

**公開状況**: `online-test` ブランチ（未 push）。`main` には未反映。
**アーカイブ（この版の1つ前）**: `archive/neo-scorebook_v2026.11.23-5.html`

**1. 経過ページ（`HistoryView`）を、テキスト速報の形式に作り直した**
- **経緯**: 野球速報サイト（球速報.com のテキスト速報）の画面を参考に、経過ページをあれに寄せたい、という依頼。参考にする要素として「文章形式の打席結果」「交代・マウンドの行」「イニング見出しと3者凡退・チェンジの行」を選んだ。右端のイニング番号ジャンプは今回は入れていない。
- **イニング見出し**: 「8回裏　◯◯の攻撃」の帯と、その回の得点。
- **1行ずつの文章**（行頭に黒い番号つき）:
  - 「マウンド 投手名」（その回の最初の投手。回の最初に投手交代があるときは出さない）
  - 打席: 「1番孫田 2Sから見逃し三振　1死」「3番松本 1Bから打って右二塁打　無死二塁」。球数・カウントは、最後の1球の前のカウントから作る（初球から／2B1Sから／フルカウントから）。結果は「中飛」「遊ゴロ」「右安打」「四球」などの言い方に直す。得点が入った打席は「2点」と付く。
  - 3アウト目の打席: 「3者凡退、チェンジ　投手名 (11球/33球)」。3者凡退でなければ「チェンジ、一塁残塁」。最終回で試合が終わっていれば「試合終了」。球数は「その回／その投手の累計」。
  - 交代: 【投手交代】A(33球) → B（投手）、【守備交代】A → B（一塁手）、【代打】、【代走】、【守備変更】。
  - 走塁: 「3球目、二塁走者が盗塁成功」「投手牽制、一塁走者が牽制死」「ボールデッドで進塁」など。
- **打席の行をタップ**すると、1球ごとの内訳が開く（従来の機能を残した）。
- **変更点**: 選手交代の行は、その打席の前に出るようにした（以前は後ろ。代打で打者が替わるため、前が正しい）。投手名は、先発・控え・交代後のオーダーから背番号で引く（`lookupName`）。
- **注意**: 走塁の行には「◯死△塁」の状況は付けていない。古い保存データで、走塁の記録が打席の中に残っていない場合は表示されない。

**2. 過去の対戦チームを、相手チームの入力で選べるようにした**
- **経緯**: 対戦した相手が過去のリストとして残っておらず、再戦のたびに入力し直していた、という指摘。
- **原因**: 一覧は過去の試合から作る作りだったが、(a) 試合の詳細データ（`game_state`）が無い古い試合を除いていた、(b) 自チームが後攻の試合では、後攻側のオーダーを相手のものとして読んでいた、(c) 最後の（交代後の）オーダーを読んでいた。
- **変更**:
  - チーム名は、保存済みの全試合の `opponent` から作る。詳細データが無い古い試合の相手も一覧に出る（その場合はオーダーを入力し直す）。
  - オーダー・控えは、その相手の最新の記録から、**スタメン**（試合開始時）を使う。先攻・後攻のどちら側の記録でも正しく読む。
  - 「自チーム以外を入力」で記録した試合は、入力した2チームの両方を一覧に入れる。
  - 一覧には「日付　◯試合・前回のオーダーが入ります」と出す。最初から開いた状態で出す。
  - 新しいテーブルは作っていない。過去の試合のデータから毎回作る。
**注意**: 相手チームごとの選手名簿としては育たない（その相手の最新の記録のオーダーだけ）。名簿として管理するなら、専用のテーブルが要る（[docs/INTEGRATION.md](../docs/INTEGRATION.md) の「選手登録を1か所に」の話とつながる）。チーム名の表記ゆれ（「千鳥が丘」と「千鳥が丘少年団」など）は別チームとして出る。

**確認**: Supabase をダミーにした環境で、経過ページ（見逃し三振、空振り三振、3者凡退、守備位置変更による投手交代）、相手チームの一覧（先攻・後攻、他チームの試合、詳細データなしの古い試合）を確認。実際の保存データや本番のデータでは未確認。

## v2026.11.23-5（2026-11-23）— 「前回のオーダーを使う」でスタメンを反映

**公開状況**: `online-test` ブランチ（未 push）。`main` には未反映。
**アーカイブ（この版の1つ前）**: `archive/neo-scorebook_v2026.11.23-4.html`

**不具合**: オーダー登録の「前回のオーダーを使う」を押すと、前回の試合の**最後のオーダー**（途中の選手交代・守備位置変更をすべて反映した状態）が入っていた。ほしいのは前回の試合の**スタメン**（試合開始時のオーダー）。
**原因**: 前回オーダーを、保存データの `game_state.lineup`（交代後の最終オーダー）から読んでいた。試合開始時のオーダーは `game_state.startingLineupA/B` に別に保存されている。
**変更**:
- スタメン（`startingLineupA/B`）から読むようにした。古い保存データなどで `startingLineup` が無いときだけ、最終オーダーを使う。
- 「自チーム以外を入力」で記録した試合は、前回オーダーの対象から外した（自チームのオーダーではないため）。直近10試合のうち、最初の自チームの試合を使う。
- 打順に入らない先発投手（DH 制）は、打順の外に戻すようにした。
**確認**: Supabase をダミーにした環境で、交代を含む前回の試合と、その後の他チームの試合を用意し、スタメンが入ること・他チームの試合が飛ばされることを確認。実際の保存データでは未確認。

## v2026.11.23-4（2026-11-23）— 投手成績のずれを修正

**公開状況**: `online-test` ブランチ（コミット `aaa8c07`）。`main` には未反映。
**アーカイブ（この版の1つ前）**: `archive/neo-scorebook_v2026.11.23-3.html`

**不具合**: 投手交代があった試合で、投手成績の回（アウト数）が合わなかった。練習試合で「4回まで sousuke → 6回1アウトまで kanata → 最後の2アウトを kiichi」と記録したところ、成績タブが sousuke 4⅓・kanata 1⅓・kiichi 0⅓ と出た（正しくは 4・1⅓・⅔）。

**原因**: 次の打者の「打席」は、前の打席が終わった時点で先に作られ、そのときの投手の背番号が打席に書き込まれる（`makeBat`）。選手交代で投手が替わっても、すでに作られた打席の投手は更新されなかったため、交代直後の打者のアウト・安打・失点などが前の投手に付いていた。

**変更**: 守備側の選手交代を確定するとき（`applyAllSubs`）、新しい投手（交代後のオーダーで守備位置が「投」の選手）を、進行中で結果がまだ入っていない打席に書き込む。野球規則と同じく、交代時にいる打者の結果は新しい投手に付く。守備位置の入れ替えだけで投手が替わる場合も同じ。

**注意**:
- すでに保存した試合は直らない（保存データ自体が前の投手の背番号になっているため）。記録し直すか、保存データを直接直す必要がある。
- 打者の途中（ボールカウントが入った後）で交代した場合、その打席の球数も新しい投手に付く。

**確認**: Supabase をダミーにした環境で、守備位置の入れ替えで投手を替え、進行中の打席の投手が新しい投手になることを確認。実際の保存済み試合のデータは見ていない。

## v2026.11.23-2（2026-11-23）— 選手交代に「守備位置を一括変更」

**公開状況**: `online-test` ブランチ（コミット `065a101`）。
**アーカイブ（この版の1つ前）**: `archive/neo-scorebook_v2026.11.23-1.html`

**変更**: 「選手交代」のメニューに「守備位置を一括変更」（玉突き交代）を追加。打順の一覧で選手ごとに新しい守備位置を選び、まとめてリストに追加できる。ベンチの選手をその打順に入れることもできる。守備位置がかぶると警告が出て確定できない。履歴（経過タブ）には「守備変更: 柳井 二→遊」の形で出る。
**経緯**: 「投手がセカンド、セカンドがショート、ショートがベンチと交代してライトに…」のような連鎖的な交代を、今の1件ずつの操作ではなく一度に処理したい、という依頼。
**内部**: 交代の種類に「守備位置変更」を追加。既存の `applyAllSubs` の仕組み（打順スロットごとの書き換え）をそのまま使い、交代記録に `outPos` を追加した。
**注意**: 依頼にあった例は最後にセカンドが2人になるため、そのままでは確定できない（重複警告）。

## v2026.11.14-2（2026-11-23 にコミット）— 「自チーム以外を入力」と試験用デプロイ

**公開状況**: `online-test` ブランチ（コミット `2c5046e`）。`https://baseball.versus.jp/test/neo-scorebook.html` に出る。
**アーカイブ（この版の1つ前）**: `archive/neo-scorebook_v2026.11.14-1.html`

**変更**:
- オーダー登録の「自チーム」タブに「自チーム以外を入力」を追加。選手管理に登録していないチーム同士の試合（例: 練習試合のソフトバンクジュニア vs 阪神タイガースジュニア）を記録できる。
- この種の試合は、試合一覧では「他」と表示し、勝敗・試合数・通算成績に含めない（背番号で選手をまとめる作りのため、混ぜると自チームの成績が崩れる）。
- `.github/workflows/deploy-test.yml` を追加。`online-test` ブランチへ push すると `/test/` に自動配置される（本番とは別フォルダ。本番の自動配置は `main` への push のときだけ）。
**経緯**: 練習試合を1試合入力して入力感を試したい、という依頼から。自チーム側も自由に入力できる設計にした。
**注意**: 保存先の Supabase は本番と同じ。試しで保存した試合は試合一覧に出るので、削除が必要。DB の定義は変わっていない（`nsb_games.game_state` の中に `myFree` / `myTeamLabel` を持つだけ）。
